Lab 7.1

conversões no papel e conferência no Python

Escolha 3 endereços IPv6 completos (podem ser os do exercício A), abrevie à mão e confira com ipaddress.IPv6Address(...).compressed.
Calcule à mão o EUI-64 de 2 MACs reais (o seu: ipconfig /all no Windows, ip link no Linux) e confira com um script Python que aplique "dividir, inserir FF:FE, inverter o bit".
Compare com o endereço link-local que seu sistema mostra. Se for diferente, seu sistema usa ID de interface aleatório (privacidade), o que é normal.
Concluí este laboratório e anotei o que observei.
Lab 7.2

seu computador e o IPv6

Execute ip -6 addr (Linux) ou ipconfig (Windows). Anote o link-local (fe80::) e, se houver, o endereço global.
ping -6 ::1 (loopback). Deve responder.
ping -6 fe80::<seu link-local>%<interface> (no Windows o sufixo é %número_da_interface, no Linux %nome, por exemplo %eth0). Explique por que o sufixo é necessário (link-local não indica por qual enlace sair).
Veja os vizinhos: ip -6 neigh ou netsh interface ipv6 show neighbors.
Concluí este laboratório e anotei o que observei.
Lab 7.3

SLAAC no Packet Tracer

Topologia: 1 roteador (por exemplo 2911), 1 switch, 2 PCs. R1 G0/0 ↔ switch ↔ PC1 e PC2. Prefixo: 2001:db8:acad:1::/64.

No R1: ipv6 unicast-routing; interface g0/0; ipv6 address 2001:db8:acad:1::1/64; ipv6 address fe80::1 link-local; no shutdown.
Nos PCs: Desktop → IP Configuration → IPv6 Configuration = Automatic.
Observe o endereço obtido e compare o ID de interface com o MAC do PC (ipconfig /all no Prompt). Confira o EUI-64 que o PC gerou.
De PC1: ping para o endereço global de PC2 e para 2001:db8:acad:1::1.
No R1: show ipv6 interface brief, show ipv6 neighbors.
Quebra e conserto: remova ipv6 unicast-routing e peça "renew" no PC (alterne o modo para Static e depois Automatic). O PC obtém prefixo? Explique.
Resultado esperado
  • O PC obtém 2001:DB8:ACAD:1:xxxx:xxxx:xxxx:xxxx e o gateway é o link-local do roteador (fe80::1).
  • show ipv6 interface brief mostra a interface com o link-local e o GUA, e estado up/up.
  • Sem ipv6 unicast-routing, o roteador não envia RA, então o PC não forma o GUA (apenas o link-local).
Concluí este laboratório e anotei o que observei.
Lab 7.4

dois roteadores, um enlace IPv6

R1 G0/1 e R2 G0/1 ligados por cabo cruzado (ou direto, se a interface suportar auto-MDIX). Use 2001:db8:acad:ff::1/64 em R1 e 2001:db8:acad:ff::2/64 em R2, e ipv6 unicast-routing nos dois.
ping 2001:db8:acad:ff::2 a partir de R1.
show ipv6 route: identifique as rotas C (conectada) e L (local, /128).
Ping ao link-local do vizinho: no IOS é preciso indicar a interface de saída (o roteador pergunta "Output Interface").
Teste: mude R2 para 2001:db8:acad:fe::2/64 e refaça o ping. Explique a falha (prefixos diferentes no mesmo enlace).
Concluí este laboratório e anotei o que observei.
Lab 7.5

(opcional): capturando NDP no Wireshark

Em um computador real na sua rede, abra o Wireshark e inicie a captura na interface ativa.
Filtro icmpv6. Faça ping -6 <endereço de um vizinho da LAN>.
Observe NS, NA e, se aparecerem, RA. Anote origem, destino (multicast solicited-node ff02::1:ffXX:XXXX) e o tipo.
Identifique o MAC de destino do quadro NS (deve começar com 33:33:ff).
Concluí este laboratório e anotei o que observei.
