Lab 3.1

ver as camadas de um ping no Wireshark

Objetivo: identificar Ethernet, IP e ICMP em um pacote real.

Abra o Wireshark e comece a capturar na interface ativa.
Na barra de filtro, digite icmp e pressione Enter.
No terminal, execute ping -c 4 8.8.8.8 (Linux/macOS) ou ping -n 4 8.8.8.8 (Windows).
Pare a captura e clique no primeiro pacote "Echo (ping) request".
No painel central, expanda, nesta ordem: Frame (camada 1: bytes capturados), Ethernet II (camada 2), Internet Protocol Version 4 (camada 3), Internet Control Message Protocol.
Preencha a tabela abaixo.
CampoSeu valor
MAC origem / MAC destino (de quem é o MAC destino?)
IP origem / IP destino
TTL e Protocol (valor numérico)
Tipo ICMP (8 = request, 0 = reply)
Resultado esperado

o MAC destino é o do seu gateway (e não o do 8.8.8.8, que está fora da sua rede local); o IP destino é 8.8.8.8; o campo Protocol é 1 (ICMP).

Concluí este laboratório e anotei o que observei.
Lab 3.2

DNS e HTTP em camadas

Objetivo: ver o DNS (UDP), o handshake TCP e o HTTP.

Inicie nova captura sem filtro de captura.
No terminal: nslookup example.com e depois curl -v http://example.com (no Windows, use curl.exe).
Filtre dns e identifique a consulta e a resposta (camada 4 = UDP, porta 53).
Filtre tcp.port == 80. Localize os três pacotes do handshake (SYN, SYN/ACK, ACK) e depois o "GET / HTTP/1.1".
Clique com o botão direito no GET → Follow → TCP Stream para ler a conversa da camada 7.

Perguntas: (a) Qual a porta de destino do DNS e do HTTP? (b) Que camada e protocolo carregam o texto "GET"? (c) Quantos pacotes TCP foram trocados antes do primeiro byte de HTTP?

Resposta esperada: (a) 53/UDP e 80/TCP. (b) Camada 7 (HTTP) dentro de TCP. (c) Três (o handshake). Se algum campo diferir (por exemplo, o site redirecionar para HTTPS), anote e compare.

Concluí este laboratório e anotei o que observei.
Lab 3.3

Packet Tracer em modo Simulation

Objetivo: ver as camadas OSI de um pacote.

No Packet Tracer, monte: PC0, Switch2960, Server-PT com cabos Copper Straight-Through.
PC0: IP 192.168.1.10, máscara 255.255.255.0 (aba Desktop → IP Configuration). Server0: IP 192.168.1.100, máscara 255.255.255.0.
Mude para Simulation (canto inferior direito) e, em Edit Filters, deixe marcados só ARP, ICMP, TCP e HTTP.
No PC0, abra Desktop → Web Browser e digite 192.168.1.100. Clique em Auto Capture / Play ou em Capture / Forward.
Clique no envelope colorido de cada evento para abrir o PDU Information e use a aba OSI Model (camadas de entrada e saída) para ver em qual camada o dispositivo processa o pacote.
Observe: o switch só chega até a camada 2; o PC e o servidor processam até a camada 7.
Resultado esperado

primeiro um ARP (o PC descobre o MAC do servidor), depois o TCP (handshake) e por fim o HTTP, com a página padrão do servidor aparecendo no navegador.

Concluí este laboratório e anotei o que observei.
